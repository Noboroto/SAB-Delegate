# Build image Linux — cây sạch, artifact generated, case-sensitivity

- File generated gitignored (Prisma client, Zod sinh ra, `dist` của shared) bị nướng cũ vào image: Docker đọc `.dockerignore`, KHÔNG đọc `.gitignore` → `COPY` lấy bất kỳ thứ gì có trên đĩa lúc build; `git pull` không chạm file gitignored nên bản trên server cũ vĩnh viễn (22/09/2026: web build đỏ TS2322 `never`, local xanh cùng commit). Dấu hiệu: local xanh, prod đỏ cùng commit → nghi artifact gitignored. **How**: Dockerfile server/web tự chạy `prisma generate` (+ build shared) trong stage build từ cây sạch; `.dockerignore` loại `**/src/generated/`, `**/.next`, `**/dist`; thử build đúng target runner và chạy lệnh gate (require PrismaClient). Coolify build từ source nên không có ngoại lệ. (nguồn: JudgeHub, QR-Production-Manager, Leaderboard)
- Prisma trong image: generate ra ngoài node_modules (stage `gen` → `backend/generated`), runner COPY vào, không có Prisma CLI/engine; stage `release` (chạy `migrate deploy`) đặt TRƯỚC `runner` để build không `--target` (Coolify) vẫn ra ảnh runtime; `prisma.config` fallback URL `postgresql://...@invalid.invalid/...` để `generate` không cần DB và `migrate` thiếu URL không đụng nhầm Postgres local. `pnpm deploy` cài lại làm mất `.prisma` → `Cannot find module '.prisma/client/default'` chỉ lộ ở stage runner. Nếu `migrate deploy` chạy lúc container start thì runner phải giữ prisma CLI + schema (runner "slim" làm hỏng boot). (nguồn: SAB-Store, Leaderboard, student-papers-manager)
- Verify trong IMAGE Linux đã build mọi thay đổi dependency/override/patch/đường import/tên file hoa-thường: macOS (APFS) và Windows không phân biệt hoa/thường, container mount `node_modules` của Mac cũng vậy. **Why**: 24/09/2026 override `stream-json` đổi `Parser.js` → `parser.js`; Mac qua hết; image Linux crash `MODULE_NOT_FOUND`, prod sập ~6 phút. **How**: `docker build --target runner` rồi `docker run --rm --entrypoint node <img> -e "require('<pkg>')"` TRƯỚC khi push `main` (push = deploy). (nguồn: JudgeHub, Leaderboard, SAB-Store)
- Module chỉ dùng cho test phải khớp một pattern exclude của `tsconfig.build.json`: helper test không phải `*.spec.ts` import file ở root repo qua hook (typecheck gồm test nên xanh) nhưng `nest build` trong image hỏng. **How**: quy ước tên `*.test-harness.ts`/`*.fixtures.ts` + exclude; kiểm `nest build -p tsconfig.build.json` ở target runner. (nguồn: Leaderboard)
- Context build là gốc monorepo (`context: .` + `dockerfile: apps/<app>/Dockerfile`); BuildKit ưu tiên `<Dockerfile>.dockerignore` hơn ignore gốc; mẫu không có `**/` chỉ khớp ở gốc context (thư mục lồng `tests`, `uploads` lọt vào ảnh). Sau mỗi đổi Dockerfile/ignore/dependency: dựng cả hai ảnh, liệt kê `/app` (không tests, `*.md`, `Dockerfile*`), đòi mọi dependency server nằm trong ảnh. `RUN chmod -R` sau COPY nhân đôi layer. (nguồn: SAB-Store)
- `pnpm deploy --prod --config.inject-workspace-packages=true` (không `--legacy` vì `--legacy` giải lại peers). Optional peer (better-auth kéo `vitest`/`vite`) lọt vào ảnh: `auto-install-peers=false`, `overrides`, `ignoredOptionalDependencies` KHÔNG gỡ; `.pnpmfile.cjs` gốc hook `readPackage` xoá `peerDependencies`/`peerDependenciesMeta` thì gỡ (373 → 316 MB). `.pnpmfile.cjs` phải COPY cùng manifest ở mọi Dockerfile và `pnpmfileChecksum` trong lockfile phải khớp. (nguồn: SAB-Store)
- `next build` import route → env validation cần biến giả (throwaway) ở stage builder; build arg lưu trong image history nên KHÔNG dùng giá trị thật; `NEXT_PUBLIC_*` inline lúc build (Coolify truyền env làm build arg), env runtime trên container không đổi được bundle. Same-origin: Next rewrite `/api/*` → server nội bộ (tên service) thay vì `NEXT_PUBLIC_API_URL` → bundle không chứa hostname API, một image chạy mọi môi trường, cookie Better Auth đơn giản, không CORS. (nguồn: ComparableTransaction, student-papers-manager, Leaderboard)
- Comment CSS có `*/` giữa chừng (`/* ... (S1/S2*/S3) ... */`) làm Turbopack production build chết "Parsing CSS source code failed" trong khi `next dev`, typecheck, ESLint, Prettier, vitest đều xanh (không đọc CSS module). **How**: viết `(S1, S2*, S3)`; coi `next build`/image build thật là cổng trước deploy. (nguồn: JudgeHub)
- `docker compose build` chỉ tạo image — container cũ vẫn chạy bundle cũ; "xong" = build + `up -d` (không kèm tên service) + báo hard-refresh; `build` xanh có thể chỉ do layer cache. Bind-mount MỘT file giữ inode cũ sau `git pull` (`nginx -t` xanh theo config CŨ) → `up -d --force-recreate <svc>`, kiểm `exec ... grep -c '<chuỗi mới>' <file trong container>`; mount cả THƯ MỤC thì không dính. (nguồn: JudgeHub, QR-Production-Manager, SAB-Store, ComparableTransaction)
- Dev container: named volume `node_modules`/`next_cache` che image → thêm dependency phải `docker volume rm <project>_node_modules <project>_next_cache` (cache Turbopack gây "Module not found" cho file không còn); không `docker compose down -v` (mất DB dev); ưu tiên `pnpm dev` native trên macOS, chỉ DB trong compose. Prisma generate mỗi OS một bản client (thư mục generated gitignore). (nguồn: ComparableTransaction)
- Script ad-hoc trên prod: KHÔNG `NestFactory.createApplicationContext(AppModule)` trong container API đang chạy (khởi động lại worker/scheduler/bind port với memory 1g → exit 137, PID 1 chết, 502 SSE); rootfs read-only nên `docker cp` thất bại → `docker exec -i <c> node --input-type=module - < script.mjs`; dùng `127.0.0.1` không `localhost` (IPv6 refused). Script seed Nest phải precompile bằng `tsc -p` (xem `mem:lessons/nestjs/di-and-build`). (nguồn: JudgeHub)
- `.gitignore` mẫu Node có dòng `logs` trần: nuốt MỌI thư mục tên `logs` (route `app/.../logs`, `components/logs`, `lib/logs`) → không bao giờ commit, build local vẫn chạy (file có trên đĩa) nhưng prod build từ git thiếu trang → 404 chỉ trên prod (đo 2026-10-15). **How**: ghi `/logs` (chỉ gốc repo); sau khi thêm thư mục mới chạy `git status --ignored` lọc thư mục nguồn; guard `nav-routes.guard` kiểm mọi route trong nav có `page.tsx` không bị ignore. (nguồn: SAB-Delegate)
