# Coolify compose — vòng đời deploy (bổ sung cho `coolify-build-from-source`)

Luật chủ repo vẫn thắng: KHÔNG `${VAR:?}`, KHÔNG named volume, KHÔNG `container_name`; dữ liệu = bind mount tuyệt đối dưới `/srv/appdata/sab-delegate/...`. Biến bắt buộc → fail-fast bằng Zod env lúc boot (không dùng `:?`).

- Mỗi lần deploy Coolify xoá + tạo lại CẢ stack compose, kể cả service không đổi: probe 1 req/s trên SAB-Store đo sập ~100 s (deploy 78), sau chỉnh `pull_policy: never`/`stop_signal: SIGTERM`/`start_interval` ổn định ~57–64 s (deploy 80/84/94); 100 s trên Coolify 4.3.23 cho cả DB. Bot+web compose ≈ 60 s mỗi deploy, KHÔNG phải "vài giây". **Why**: DB restart + migration mỗi lần deploy code là không chấp nhận được. **How**: [KHUYẾN NGHỊ, chờ chủ repo xác nhận] Postgres là resource Coolify RIÊNG, không nằm trong compose bot/web; job pg-boss phải chịu được Postgres restart giữa chừng; deploy lúc không có poll/hẹn giờ sắp tới hạn. (nguồn: SAB-Store, coolify)
- Coolify tiêm MỌI env của resource thành `ARG` vào MỌI stage Dockerfile ("Added 56 ARG declarations") và `--build-arg` cho cả secret. `NODE_ENV=production` có mặt lúc `RUN pnpm install` → bỏ devDependencies → `vite: not found` (2 lần deploy hỏng); secret vào `docker history`. Build local KHÔNG tái hiện (không có ARG). **How**: mọi `pnpm install` ghi rõ `--prod` hoặc `--no-prod` (pnpm 12 từ chối `--prod=false`); biến runtime-only (token Discord, DB URL, Better Auth secret) đặt `is_buildtime=false` ngay khi tạo; chỉ `NEXT_PUBLIC_*` cần build-time (không chứa secret); sau deploy `docker history --no-trunc <image> | grep -c '<TÊN_SECRET>='` = 0; mô phỏng bằng cách tự chèn `ARG` sau `FROM`. Secret cũng bị tiêm vào container không liên quan → chỉ khai biến cho resource thực sự cần. (nguồn: SAB-Store, coolify)
- Service migrate/seed/tools không `profiles` sẽ chạy lên DB prod mỗi deploy (Coolify deploy = `compose up`). Mẫu an toàn: service `migrate` one-shot (hoặc `release`: `pg_dump -Fc` → `prisma migrate deploy`) là `depends_on` của server/bot dạng MAP với `condition: service_completed_successfully` (dạng list KHÔNG chờ: web/worker/cron khởi động song song); seed/dump/sync/reset để `profiles: [tools]`, không bao giờ default; cờ drop/reset DB opt-in. **Why**: thư mục app Coolify lúc runtime chỉ có `.env` + `docker-compose.yaml`, không source → `profiles` không chạy tay được; image `migrate` riêng thì `build app` không rebuild nó (báo "No pending migrations" exit 0 trong khi app boot schema mới). **How**: dùng MỘT image/target cho cả app và release; tránh `docker compose run` (không `--no-deps` sẽ recreate postgres); migration luôn tương thích 2 phiên bản (expand → contract) vì release chạy TRƯỚC khi app mới thay app cũ. (nguồn: coolify, data-tuyensinh, openproject-docker, QR-Production-Manager, JudgeHub)
- Container phải sống sót qua `docker restart`/dockerd restart (apt upgrade/unattended-upgrades nâng docker-ce làm mọi container restart 1–2 phút): entrypoint idempotent, không ghi `/tmp` rồi chown (host đặt `fs.protected_regular=2` → lần restart sau "Permission denied", crash-loop, 503/502 tới 8 giờ); ghi vào thư mục không sticky và `rm -f` trước khi ghi. `restart: unless-stopped` + healthcheck (`restart: always` cũ thời Portainer sống lại sau `stop` tay → bản bot cũ chạy trùng token). **How**: checklist deploy có "`docker restart <c>` → healthy"; sau reboot kiểm không có bản bot cũ sống lại; `docker update --restart=no` rồi `docker stop`, `docker rm -f` (không `-v`). Khôi phục khẩn: `docker compose -f <file Coolify render> -p <uuid> up -d --no-deps --force-recreate <svc>`. (nguồn: coolify, SAB-Store)
- Trước khi push nhánh auto-deploy: backup DB (`pg_dump -Fc`, đếm row trước/sau) + `docker compose -f coolify.compose.yml config -q` (truyền giá trị giả cho biến không default; không in config đã nội suy). **Why**: lỗi validate compose khiến deploy fail im lặng trong khi container cũ vẫn chạy (kẹt 17 ngày; deploy #67 chết ở bước validate sau khi prod đã dừng). **How**: sau push kiểm status deploy mới nhất + tuổi container: `docker exec coolify-db psql -U coolify -d coolify -At -c "select status from application_deployment_queues order by id desc limit 1"` (log: cột `logs` theo id); xoá env Coolify thừa đang ĐÈ default `${TAG:-...}`. (nguồn: openproject-docker, SAB-Store)
- Webhook GitHub có thể không bắn (29/09 không có dòng `webhook.deployment.queued`) → sau push `main` xác nhận deployment được tạo (< 10 s); kích tay bằng HMAC-SHA256 payload push với `manual_webhook_secret_github` đã giải mã (cột DB mã hoá). Sửa env không qua UI: `php artisan tinker` với `\App\Models\EnvironmentVariable` (không UPDATE thẳng cột `value`), secret truyền `docker exec -e KEY` không kèm giá trị. (nguồn: SAB-Store)
- Cấm bấm "Convert to directory" ở Persistent Storage (xoá nội dung bind mount, coollabsio/coolify#2873); sửa bind mount trong file compose. Bind-mount FILE: file phải có trên host trước khi push (không thì Docker tạo thư mục trùng tên); inode đổi sau `git pull` (xem `mem:lessons/deploy/docker-image-build`) → ưu tiên COPY config vào image hoặc mount cả thư mục. Checkout server bị chmod +x file bind → `git config core.fileMode false` ở checkout đó. (nguồn: coolify, JudgeHub, QR-Production-Manager)
- Tên SERVICE là network alias (Coolify tự đăng ký; không cần `networks:`): web gọi `http://<service>:<port>`, đặt tên service backend đúng alias, đừng đổi tên tuỳ ý (Coolify xoá container service cũ, bind mount còn nguyên). Chọn container app trên host đông project bằng label `com.docker.compose.project` + `com.docker.compose.service`. 502 trong khi mọi container healthy = container không chung network proxy: `docker inspect <c> --format '{{json .NetworkSettings.Networks}}'`; Traefik trả 503 (không phải 404) cho hostname không có route. (nguồn: SAB-Store, data-tuyensinh, coolify)
- Compose prod: không `ports:` cho Postgres/Redis (Docker DNAT bỏ qua ufw, `DOCKER-USER` rỗng → publish ra internet; một stack dev chạy 5 tuần trên host prod vì `docker compose up -d` trần), dùng `expose`/mạng nội bộ; tên file compose dev khác prod. `stop_grace_period` phù hợp job pg-boss đang chạy (JudgeHub api 120 s → deploy gián đoạn vài phút). Image DB pin `postgres:<major>@sha256:...`, không `:latest` (major mới nâng data dir tại chỗ, không quay lại); nâng major = dump/restore có diễn tập. (nguồn: JudgeHub, coolify)
- Let's Encrypt giới hạn 5 cert trùng hostname/tuần → trỏ DNS đúng TRƯỚC khi bật domain web trong Coolify, không thêm/xoá domain lặp lại, thử ACME ở staging. Không tự nâng Coolify (hành vi đã đo trên bản pin; nâng = đo lại). Watch Paths áp mọi loại app; `[skip ci]`/`[skip cd]` bỏ qua deploy (commit chỉ docs). Rollback từ build-from-source về image: revert `image: 127.0.0.1:5000/<repo>:<tag>` + `pull_policy: always` và XOÁ khối `build:`; ghi tag image cuối trước cutover. (nguồn: coolify, SAB-Store)
- Cổng deploy: downtime < 30 s thì deploy ngay (chứng minh bằng probe 1 req/s suốt lần deploy); không đảm bảo thì chọn lúc 15 phút không có người dùng; verify trên localhost bằng dữ liệu clone từ prod (không dữ liệu cá nhân). Với bot ít người dùng cổng nhẹ hơn nhưng vẫn tránh lúc có poll/hẹn giờ sắp chạy. (nguồn: SAB-Store)
