# Phụ thuộc & Syncthing

## Phụ thuộc
- `pnpm --filter <ws> add <pkg>` KHÔNG kèm `@version` (số tra lúc khảo sát chỉ là ảnh chụp; pnpm giải là nguồn sự thật); sau khi cài đọc version thật trong `package.json` rồi mới ghi vào commit/tài liệu; kết luận kỹ thuật xác minh trên version cụ thể thì ghi version đã kiểm. Ngoại lệ có bằng chứng thì ghim kèm điều kiện gỡ (Better Auth, undici đã đo). (nguồn: JudgeHub, attendance-hcmus)
- Dùng bản stable/LTS mới nhất (không rc/beta/canary), Node theo LTS, `@types/node` cùng major với runtime, image ghim `tag@sha256` và dùng chung digest nếu cùng image. `pnpm audit --prod`, `pnpm outdated` VÀ `npm view <pkg> version` cho dependency trực tiếp ở ĐẦU phiên và trước mỗi deploy (outdated/audit bỏ sót Next 16.2.9 → 16.3.x vá RCE). Giữ một package ở bản cũ chỉ khi có bằng chứng (link issue/peer range/changelog) + điều kiện gỡ, ghi vào `docs/dependencies.md`. Theo dõi: TypeScript 7 chờ typescript-eslint #10940, Prisma 8 còn rc. (nguồn: Leaderboard, QR-Production-Manager, attendance-hcmus)
- Commit CHỈ thêm dependency FAIL knip (unused deps) → dependency cùng commit với code dùng. Lockfile pnpm có thể bị `pnpm install` ghi lại — xem diff trước khi commit. Sau khi thêm dependency kiểm kích thước image (xem `mem:lessons/deploy/docker-image-build`). (nguồn: SAB-Store, JudgeHub)
- `undici` ≥ 8.11.2 (xem `mem:lessons/nestjs/http-and-runtime`); `@rc-component/util@1.13.0` cần patch (xem `mem:lessons/testing/vitest-pitfalls`); Prisma 7 + adapter-pg; mọi bản giữ lại ghi lý do + điều kiện gỡ vào memory. (nguồn: Leaderboard, QR-Production-Manager)

## Syncthing (Mac ↔ Windows, whitelist repo)
- gitignore ≠ stignore: file gitignored (`node_modules`, `.next`, `dist`, Prisma client generated — mỗi OS một bản, data dir Postgres dev, `.code-review-graph`, `.env`) vẫn bị đồng bộ nếu không có trong `.stignore-shared`; luật khớp-đầu-tiên → khối riêng từng repo phải đặt TRÊN dòng re-include git của repo. State git riêng máy (`index`, `*.lock`, per-machine `config`, `ORIG_HEAD`, `FETCH_HEAD`, `COMMIT_EDITMSG`, `logs/**`) phải loại. Thiếu khối này Mac mang `core.filemode=false` của Windows (gốc sự cố hook mất bit exec). Kiểm bằng REST `/rest/db/file` (`ignored`) sau rescan; API key đọc vào biến, không echo. (nguồn: tcps, ComparableTransaction, SAB-Store)
- Cấm `(?d)` trên thư mục VCS/dữ liệu (từng xoá `.git` của 173 repo trên Windows). Luật chung `(?d)` cho thư mục tên b-u-i-l-d nuốt thư mục nguồn cùng tên (Next route `app/api/.../build`) → ngoại lệ `!` đặt TRÊN luật chung; trước khi đặt tên thư mục nguồn `build`/`vendor`/`dist`/`out` kiểm luật chung. (nguồn: ComparableTransaction)
- Một máy ghi git tại một thời điểm: máy A commit xong thì dừng (báo hash = khoá), máy B chờ "Up to Date" rồi `git reset` (index riêng), kiểm HEAD + status sạch; không fetch/pull ở máy không ghi; không `git stash` khi agent khác đang sửa file; sau bàn giao tìm `*.sync-conflict-*` (hai máy cùng ghi refs sinh 13 file conflict trong `.git`). Máy thứ hai lần đầu: `core.filemode true`, `core.symlinks true`, `core.precomposeunicode true`, unset `core.autocrlf`, `core.ignorecase false`, đặt remote origin + refspec + upstream, `git reset`, `chmod +x` script shell (Syncthing `ignorePerms`). `.gitattributes` `* text=auto eol=lf` + prettier `endOfLine: lf`. (nguồn: JudgeHub, SAB-Store, openproject-docker, laptop-shortlist)
- Dữ liệu sống của DB (bind mount trong repo, data dir Postgres, `backups/`) KHÔNG nằm trong thư mục sync (bản copy giữa chừng hỏng): Postgres dev đặt ngoài `~/Github` hoặc loại trong `.stignore-shared`; chuyển dữ liệu giữa máy bằng dump/restore. Hệ điều hành không phân biệt hoa/thường → đổi hoa/thường tên file kiểm trong Docker (Linux). Pattern `*.snap` trong `.stignore` nuốt cả file track. (nguồn: openproject-docker, SAB-Store, JudgeHub)
