# Prisma 7 + pnpm traps measured while building the data layer (2026-10-13)

- `PrismaClient`'s constructor returns a Proxy: an instance of a class extending it is NOT `instanceof` that class. `expect(svc).toBeInstanceOf(PrismaService)` fails and vitest then recurses forever printing the Proxy -> `RangeError: Maximum call stack size exceeded`. Assert booleans instead (`typeof svc.onModuleInit === 'function'`, `Object.is(a, b)`).
- Nest `TestingModule.close()` re-awaits a failed `init()` and rethrows it: a spec that expects `onModuleInit` to reject must capture the rejection and call the shutdown hook itself, not rely on `afterEach(close)`.
- Generator `prisma-client-js` writes the generated client to the sibling `<virtual store>/node_modules/.prisma/client`, not into `@prisma/client`. After `pnpm deploy` in a Dockerfile, copying only `@prisma/client` breaks with `Cannot find module '.prisma/client/default'`. Copy `.prisma` too (resolve via `dirname(require.resolve('@prisma/client/package.json'))/../../.prisma`) and fail the build on `Prisma.ModelName` missing. `node -p` prints `undefined` after `console.log` output — use `node -e` for path capture.
- prisma-zod-generator never cleans its output dir: after a schema change stale model files import enum files that no longer exist and `tsc` of `@sab/shared` fails. `db:generate` must `rmSync` the output dir first.
- `git stash` does not stash gitignored generated files, and a hook-triggered `pnpm install` against the stashed `package.json` prunes packages (16 removed). Don't stash to commit a subset while generated code or deps differ; finish the work and commit in order instead.
- `prisma migrate diff --from-config-datasource --to-schema <dir> --exit-code` against a DB built by `migrate deploy` reports "No difference detected" with hand-written CHECK migrations present (diff ignores CHECKs; specs must cover them). A `TEXT[] DEFAULT ARRAY[]` column made NOT NULL by hand did not re-emit.
- JS `String.replace(str, replacementString)`: `$'` / `$&` in the replacement string are special patterns — use a function replacer when the replacement contains `$`.
