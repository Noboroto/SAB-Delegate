# Prisma migration — quy trình an toàn

- Agent CHỈ chạy `prisma migrate deploy`; cấm `migrate dev`/`migrate reset`/`db push` trên mọi DB không phải máy dev (hỏi tương tác, có thể reset/reseed). Cần migration mới: người chạy `migrate dev` ở máy dev, hoặc agent sinh SQL bằng `prisma migrate diff` rồi hand-write và commit. Script `db:migrate` = `prisma migrate deploy`. Partial unique index, generated column, view, extension (`pg_trgm`) viết SQL tay trong file migration, không trộn `db push`. (nguồn: JudgeHub, Leaderboard, QR-Production-Manager, attendance-hcmus, SAB-Store)
- Prisma 7: `migrate diff` dùng `--to-schema` (không `--to-schema-datamodel`), bỏ `--from-url/--to-url`; `migrate diff` ghi lại default `dbgenerated` nếu không viết ĐÚNG như Postgres in ra; `ALTER COLUMN ... SET NOT NULL` thêm tay cuối migration không bị coi là drift; mỗi ràng buộc SQL hand-write cần comment `///` tương ứng trong `schema.prisma`; Prisma 7 phải có adapter (`@prisma/adapter-pg`), `new PrismaClient()` trần hỏng. Migration cần URL trực tiếp (không qua pooler transaction). (nguồn: JudgeHub, SAB-Store, Leaderboard)
- Migration phải được COMMIT + push trước khi deploy: deploy prod đầu tiên áp ĐÚNG 0 thay đổi vì quên commit (dev dựng từ working tree thấy migration, Coolify build từ git thì không); Prisma in `No pending migrations` exit 0. **How**: sau deploy kiểm hai nguồn độc lập: `SELECT migration_name, finished_at FROM _prisma_migrations ORDER BY started_at DESC` khớp thư mục migration, và đếm dữ liệu thật so với mốc đo TRƯỚC khi chạy. (nguồn: JudgeHub, attendance-hcmus)
- Migration luôn additive/tương thích ngược với code đang chạy: container cũ vẫn phục vụ trong lúc deploy (Coolify) và process đã nạp model giữ column cache cũ tới khi restart. Xoá/đổi tên cột/bảng = expand → deploy → contract (hai deploy). Thêm cột NOT NULL kèm default/backfill; migration phải chạy được trên bảng đã có dữ liệu (không `RAISE EXCEPTION` khi bảng còn dòng); không sửa migration đã áp. (nguồn: openproject-docker, data-tuyensinh, attendance-hcmus)
- Trước CHECK/NOT NULL mới đếm dữ liệu thật trên bản sao prod; diễn tập migration lớn: `pg_dump -Fc` prod → DB tạm → restore → `migrate deploy` → `query_to_xml` đếm từng bảng trước/sau → diff (`CREATE DATABASE ... TEMPLATE` không dùng được khi còn kết nối). Seed local giống cấu trúc prod nhưng KHÁC không gian giá trị nên test xanh sai chỗ — không nghiệm thu bằng seed. Chuyển quick.db → Postgres cần bước import riêng, idempotent. (nguồn: openproject-docker, data-tuyensinh, SAB-Store)
- DB đã có dữ liệu trước baseline: `prisma migrate resolve --applied <baseline>` (onboard `0_init`). `P3009` (migration lỗi nằm lại): khôi phục DB về trước migration rồi `migrate resolve --rolled-back <tên>`; `--applied` chỉ khi đã tự kiểm DB khớp. Khôi phục: dừng app, `pg_restore --clean --if-exists`, đọc lại số dòng bằng kết nối MỚI (pool đang mở có thể trả trạng thái cũ). (nguồn: Leaderboard, QR-Production-Manager, JudgeHub)
- Seed/RBAC-catalog không nằm trong migration: seed idempotent (upsert), tách khỏi migrate; `db:seed` có thể reset dữ liệu/mật khẩu → dùng lệnh sync riêng cho phần catalog (quyền/role), xoá cache liên quan, kiểm bằng endpoint đếm. (nguồn: JudgeHub)
- Sau `prisma generate`: build lại `packages/shared` rồi mới typecheck/test (dist cũ cho typecheck xanh giả); sau migrate/generate restart dev server. Thứ tự trong `predev`/`pretest`/`prebuild`: `prisma generate` → build shared. Schema mới → rà DTO dựng bằng `.omit()` xem có lộ cột mới không. (nguồn: JudgeHub, QR-Production-Manager, ComparableTransaction)
- Migration trên nhánh có bước dựng/deploy tự động áp lên DB thật ngay (Vercel preview từng áp migration lên DB prod); Coolify chỉ deploy `main` nhưng nguyên tắc giữ: không chạy migrate trong bước dựng image; migration trên nhánh auto-deploy là live ngay. (nguồn: ComparableTransaction, attendance-hcmus)
- Script CLI đọc stdin bằng readline sau `await` dài thoát im lặng exit 0 (stdin file/pipe ngắn đã đóng, event loop rỗng): tạo `readline.createInterface` + `rl[Symbol.asyncIterator]()` ngay đầu hàm trước mọi `await`, thêm `process.once('beforeExit')` đặt exitCode ≠ 0 nếu chưa báo hoàn tất. Áp cho script import quick.db/sqlite → Postgres. (nguồn: Leaderboard)
