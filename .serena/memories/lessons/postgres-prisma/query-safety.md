# Truy vấn Prisma — an toàn, đẩy xuống DB, giao dịch

- Prisma `contains/startsWith/endsWith` → `LIKE ('%' || $1 || '%')` KHÔNG escape; `equals` + `mode:'insensitive'` → `ILIKE $1` tức PATTERN (đo Prisma 7.10: `equals:'%'` khớp 13/13 user, `_` khớp mọi ký tự, tìm `_` khớp 60/60 dòng); `in` + insensitive an toàn (`LOWER(col) IN (LOWER($1),...)`), `equals` không mode an toàn (`=`); escape `\` rồi `%`, `_` chạy được. **Why**: lookup "chính xác" có thể ra bản ghi bất kỳ. **How**: 3 helper chung (`escapeLike`, `caseInsensitiveFilter`, `caseInsensitiveEquals`) + guard test cấm `mode:'insensitive'` inline; tra tên guild/role/username chính xác dùng `equals` không mode hoặc `in`. (nguồn: JudgeHub, Leaderboard, attendance-hcmus)
- Trả row Prisma ra response rò cột mới theo thời gian: `return {...row}` với `include:` — cột `ipChain` thêm sau chảy thẳng ra người dùng cuối, không test nào thấy; DTO sinh từ Prisma rồi `.omit()` cũng KHÔNG fail-closed, chỉ `.pick()` hoặc `select` tường minh mới fail-closed; comment "đã gác bởi X" là lời hứa chứ không phải cơ chế. **How**: endpoint trả dữ liệu nhạy cảm (token, secret webhook, config guild) dùng `select` + `.pick()`; review migration thêm cột → hỏi "endpoint nào đang spread row của bảng này". (nguồn: JudgeHub, attendance-hcmus, QR-Production-Manager)
- Thứ tự bắt buộc: Prisma Client API (`where/orderBy/take+skip/cursor/_count/groupBy/aggregate`, `updateMany` có điều kiện) > `$queryRaw` tham số hoá (`Prisma.sql`, sort key qua allowlist; view/generated column) > JS. Tiêu chí: thao tác có GIẢM số dòng truyền về không? Có → DB (cấm `findMany` rồi `.filter/.sort/.slice/.length`); không (dòng đằng nào cũng cần) → group trong JS là đúng. Raw SQL bỏ qua soft-delete extension (thêm điều kiện tay), dùng tên cột đã `@map` (camelCase nháy kép), không hardcode `public.`. (nguồn: JudgeHub, Leaderboard, QR-Production-Manager, ComparableTransaction, attendance-hcmus, data-tuyensinh)
- Phân trang: sort có khoá phụ ổn định (`id`), lọc TRƯỚC phân trang, không đếm bằng `.length`; N+1 → `include/select` hoặc `where id in [...]`. Tìm có dấu/không dấu tiếng Việt: cột `*_unaccent` + GIN `pg_trgm` thay `contains` insensitive; hàm chuẩn hoá JS và SQL phải khớp nhau + test quét code point; cột mới cần search thì thêm index cùng migration. (nguồn: JudgeHub, QR-Production-Manager, ComparableTransaction)
- Màn hình và export (CSV/XLSX) cùng mục đích PHẢI dùng chung một hàm service + một Zod query (export chỉ bỏ phân trang, có trần số dòng, cursor/stream); hai truy vấn cho cùng dữ liệu là lỗi vì hai nguồn số lệch âm thầm. Export lớn: đếm và từ chối (413) TRƯỚC byte đầu; lỗi giữa chừng thì destroy stream. Tác vụ nặng (export, báo cáo) không chạy trong request path: DB trước, rồi worker/pg-boss riêng, rồi client; buộc chạy Node thì ghi lý do + giới hạn tài nguyên. (nguồn: JudgeHub, QR-Production-Manager, attendance-hcmus)
- `$transaction` interactive ngắn, có `timeout/maxWait`; KHÔNG gọi dịch vụ ngoài (Discord API, email) bên trong — transaction có thể thử lại/huỷ còn tác dụng phụ ngoài thì không; gọi ngoài SAU commit (pg-boss job) và ghi nhận "đã gửi" để idempotent. Chạm bản ghi theo id tăng dần; chặn tranh chấp bằng `updateMany` có điều kiện (count 0 → từ chối) + UNIQUE khoá idempotency; ghi sổ (ledger) thay vì cộng trừ trong JS; advisory lock theo thứ tự khi cần. Lock ngoài (Redis) chỉ để single-flight cho side-effect, không phải bảo đảm đúng đắn. (nguồn: Leaderboard, QR-Production-Manager, SAB-Store)
- Bất biến kiểu "còn ít nhất một admin" dùng `FOR UPDATE` trong CÙNG transaction ghi (race-free), định nghĩa "active admin" ở một file; hook phụ chỉ là backstop. Áp cho gỡ role admin cuối cùng trên web. (nguồn: ComparableTransaction)
- Cột Json đọc ra là `any` runtime → Zod parse ở biên service (xem `mem:lessons/zod-dry/schema-rules`). Backtick trong comment `--` bên trong `$queryRaw\`...\`` kết thúc template → `Parsing error: ',' expected` dòng sau: viết tên định danh trần; chạy `npx eslint <file>` ngay (diagnostics serena không đủ). (nguồn: JudgeHub, attendance-hcmus)
- Pool: `@prisma/adapter-pg` bỏ qua `connection_limit` trong URL; pool là `pg.Pool` cấu hình qua option `max` của adapter (`DB_POOL_MAX`); pg-boss giữ pool riêng → tính tổng so `max_connections`, hạ pool trong config test; Prisma 7 + adapter-pg từng cạn pool — đặt pool size + timeout trước khi chạy replica thứ hai. Query model luôn gắn schema cố định (`"public"."user"`), `search_path` không chuyển hướng (xem `nest-and-db-tests` về option `schema`). (nguồn: ComparableTransaction, attendance-hcmus, Leaderboard)
