# Bằng chứng khi verify — test xanh chưa phải hành vi đúng

- Test xanh không chứng minh hành vi: mock dựng "thế giới" không có ở call site (mock `t()` trả lại key, harness hardcode `open: true` + `onSuccess: vi.fn()`, fixture mượn hình dạng luồng khác). Tiêu chí: xoá sạch phần đấu dây production mà test vẫn xanh thì đó không phải test. **How**: test ở tầng call site; reviewer chất lượng test hỏi đúng câu đó; hàm có nhánh chính/fallback thì hỏi fixture rơi vào nhánh nào. (nguồn: JudgeHub, attendance-hcmus)
- `status: done` phải có caller: audit 31 phase "done" → 17 đúng, 8 thiếu một mảnh, 6 dựa trên code 0 nơi gọi (typecheck/lint/1021 file test đều xanh). Optional prop, provider Symbol (Nest suy `any`), hàm export lẻ là ba chỗ typecheck không bảo vệ. **How**: trước khi đánh done chạy `find_referencing_symbols` trên symbol chính (0 caller = chưa done); tick từng ô checklist kèm `file:line`. (nguồn: JudgeHub)
- Exit code 0 chỉ chứng minh lệnh chạy xong → đọc lại TRẠNG THÁI ĐÍCH: container image sha, `_prisma_migrations`, env hiệu lực, GET lại tài nguyên. Hai tham số lẽ ra khác nhau mà cho CÙNG kết quả = nghi tham số chưa được áp. **Why**: script in "Done/published/No pending migrations" mà prod giữ giá trị cũ; script nền `...; git commit; echo exit=$?` báo 0 trong khi pre-commit ĐỎ. **How**: sau commit/push nền đọc `git log -1` + đuôi log hook, không tin trạng thái task. (nguồn: JudgeHub, attendance-hcmus, SAB-Store)
- Script vận hành (backup/migrate/deploy) phải read-back mục tiêu trước khi in "OK", phân biệt "không tìm thấy" với "đã xong", dùng `trap ... EXIT` dọn container tạm. **Why**: hai script backup báo thành công giả nhiều tháng (tạo bucket rỗng rồi in "enabled", `psql -t` đếm khoảng trắng nên phải `-tA`, nhánh thiếu file bị bỏ qua im lặng rồi PASS). **How**: backup Postgres có restore-test thật. (nguồn: JudgeHub)
- Live-verify cả đường THẤT BẠI: liệt kê điểm có thể ném giữa lần ghi đầu và cuối (Prisma `$transaction`, job pg-boss, Discord API lỗi giữa hai lần ghi DB), kích một cái và kiểm rollback trên Postgres thật. **Why**: PATCH kèm mã trùng xoá dữ liệu con rồi trả 409 — đường thành công xanh hoàn toàn. (nguồn: JudgeHub, attendance-hcmus)
- Verify trên artifact sẽ ship (image build thật), không trên bản viết lại; phép đo "vi phạm có bị bắt không" phải ghi được CÓ vi phạm thật. **Why**: "3492 nút, 0 lệch" chạy trên bản Python viết lại; số thật lệch (19/21 thành 13/21). (nguồn: JudgeHub, attendance-hcmus)
- Mệnh đề phủ định rộng ("không ai gọi", "chưa từng", "không còn") phải tìm chữ giới hạn trong lệnh (pathspec, `grep -v`, regex, vai trò) rồi chạy lại không giới hạn; `grep -vE "\.test\.(ts|tsx)$"` thay vì `grep -v test` (giấu mọi file `Contest*`). Đếm bằng `SELECT count(*)` read-only thay vì suy từ git history. (nguồn: JudgeHub, attendance-hcmus)
- Phân biệt "đặc tả/thiết kế" với "đã quan sát": tài liệu yêu cầu không phải mô tả hệ thống; một con số ước lượng chưa đo không được neo nhiều quyết định (biên độ 6.25×). **How**: báo cáo scout/plan ghi "design" hay "measured" kèm nguồn đo. Trước khi báo lỗi từ nội dung file: `git fetch` + `git status -sb` (checkout có thể tụt remote). (nguồn: dtl_app-master)
- Đo thời gian chỉ tin A/B xen kẽ (cùng cấu hình đo 349 s vs 207 s trong một phiên); kiểm worker vitest mồ côi trước khi đo; số đo ghi vào memory, không vào AGENTS.md. Đề xuất "siết bảo mật" cũng phải đo trước khi áp (ví dụ pino redact `**`). (nguồn: JudgeHub, Leaderboard)
- Tra tài liệu hiện hành (context7) trước khi áp pattern, kể cả thứ tưởng đã thuộc: mẫu cũ trong repo chỉ chứng minh "từng chạy". **Why**: thanh tiến độ làm theo trí nhớ sai 3 điểm (AntD 6 có `<Spin percent="auto" />`, ARIA bất định bỏ `aria-valuenow`, `aria-busy` về `false` trong `finally`). Agent đã spawn theo trí nhớ sai thì nhắn đính chính. (nguồn: JudgeHub)
- Cổng đóng wave: đọc log container HAI lần (startup và sau khi có traffic), live-verify cả downstream suy từ `get_impact_radius_tool`, lặp nếu bẩn. **Why**: lỗi thật (SQL sai, BigInt không serialize, Zod parse ném, P2025, 4xx) chỉ nổ sau khi request đi qua. Reviewer đọc FULL file đã commit, không chỉ diff. (nguồn: JudgeHub)
- Test chạm cấu hình dùng chung phải chụp ở `beforeAll`, khôi phục sau (không xoá mù); không mock/fixture bịa để qua cổng (seed thực tế thì được). Agent được tạo dữ liệu test trên DB local/preview nhưng PHẢI theo dõi để xoá đúng thứ đã tạo, báo đã tạo gì; không bao giờ trên production. (nguồn: ComparableTransaction, attendance-hcmus)
