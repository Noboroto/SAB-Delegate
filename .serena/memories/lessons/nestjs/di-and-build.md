# NestJS — DI, build, dependency

- `tsx`/esbuild KHÔNG emit `emitDecoratorMetadata` → script khởi động Nest DI thật (`createApplicationContext(AppModule)`) ném `UndefinedDependencyException ... undefined at runtime`; `@swc-node/register` và `ts-node@10` cũng hỏng trên Node 24 + commonjs + import `.js`. **How**: `apps/server` build bằng `tsc`/`nest build` (khác bot cũ chạy thẳng `tsx`); script seed/migration Nest precompile (`tsc -p tsconfig.seed.json`, `files:[seed.ts]`, `noEmitOnError`) rồi `node dist-seed/...`; vitest với decorator cần plugin swc. ESLint không có `noUncheckedIndexedAccess` như tsc → `arr.at(i)` + guard thay `arr[i]!`. (nguồn: JudgeHub)
- Tham số constructor `?` của TypeScript vô nghĩa với DI → dùng `@Optional()`; type alias phát `design:paramtypes = Object`. Mỗi service/module mới có boot spec qua container (xem `mem:lessons/testing/nest-and-db-tests`). Provider Symbol suy `any` — typecheck không bảo vệ. (nguồn: JudgeHub)
- `tsconfig.base.json` bật `incremental: true`: `tsc --noEmit` (`pnpm typecheck`) vẫn ghi `tsconfig.tsbuildinfo`; `nest start --watch` thấy "đã cập nhật" nên không emit trong khi `deleteOutDir: true` đã xoá output → `Found 0 errors` rồi `Cannot find module dist/main`. **How**: đặt `tsBuildInfoFile` VÀO trong outDir (hoặc tắt incremental ở config build); gặp triệu chứng thì `rm -f tsconfig.tsbuildinfo`, đừng tìm lỗi ở tsconfig/main.ts. (nguồn: JudgeHub)
- `@nestjs/platform-fastify@11.2.6` ghim CỨNG `fastify: 5.11.3` dù app khai `^5.12.5`: kiểm `grep -n "^  fastify@" pnpm-lock.yaml`, vá bằng override `"@nestjs/platform-fastify>fastify": "^5.12.5"`. `@types/node` cùng major với runtime image (26 trên Node 24 là lệch); `typescript-eslint` mới siết `unbound-method`; nestjs-zod peer chỉ tới Nest ≤ 11 (Nest 12 dùng Standard Schema gốc: `@Body({ schema })`/`@Query({ schema })` + `StandardSchemaValidationPipe`, Swagger qua `standardSchemaConverter`/zod-openapi). **How**: kiểm `peerDependencies` trước khi nâng; giữ bản cũ chỉ khi có bằng chứng + điều kiện gỡ ghi vào memory; hook full suite bắt, test hẹp của agent không. (nguồn: JudgeHub, Leaderboard, QR-Production-Manager)
- Thứ tự tắt: Nest đóng worker ở `onApplicationShutdown`, SAU mọi `onModuleDestroy` (Prisma/kết nối đã ngắt) → job đang chạy gặp kết nối chết. **How** (pg-boss): `boss.stop({ graceful: true })` trước `app.close()`/Prisma `$disconnect`; kiểm thứ tự shutdown hook của Necord (`client.destroy()`) so với Prisma; hàm worker khai đủ tham số nếu lib kiểm `processor.length`; retry không được đốt attempt khi chỉ "hoãn". (nguồn: Leaderboard)
- Gắn handler `'error'` cho mọi client mạng (pg-boss, Prisma pool, discord.js `Client`); không mở kết nối trong decorator metadata lúc import. (nguồn: Leaderboard)
- Fail-fast lúc boot: validate env bằng Zod ngay khi khởi động (token Discord, DB URL, Better Auth secret ≥ 32 ký tự, trustedProxies) và `onModuleInit` kiểm kết nối DB/phiên bản migration; thiếu/yếu secret thì crash — restart loop là thiết kế, không phải lỗi cần né; rollback hạ tầng phải revert cả phần kiểm. Thay cho `${VAR:?}` bị Coolify làm hỏng. Giá trị trùng/suy ra khai MỘT lần (`APP_URL` là origin công khai duy nhất; `BETTER_AUTH_URL`, CORS suy ra; operator chỉ đặt `POSTGRES_*`, code dựng `DATABASE_URL` có URL-encode); suy ra bằng `.transform` trong schema env Zod dùng chung, có test; `.env.example` đầy đủ + test đối chiếu. (nguồn: SAB-Store, attendance-hcmus, Leaderboard, QR-Production-Manager)
- Authorization CHỈ enforce ở guard server (`@CurrentUser()` + auth service; `@RequirePermissions` method-level override class-level qua `getAllAndOverride`); `proxy.ts` Next chỉ redirect lạc quan theo cookie; client mutation qua một wrapper fetch xử lý 401/403 (`fetch` trần resolve ở 403 và UI báo thành công giả). Một câu hỏi quyền có 4 bề mặt tự trả lời thì 3/4 rò → gom thành MỘT predicate trong `packages/shared` (vd `canManageGuild`). Probe health tách nhỏ, không lộ `/system/health` đầy đủ cho role thấp. (nguồn: JudgeHub, ComparableTransaction)
- Validation chỉ validate: handler chọn field tường minh (chống mass-assignment), không gán nguyên body vào `create/update`; mã lỗi là hằng/enum ở một file (`ErrorCode`, drift-guard test, server trả mã — web dịch); không nuốt lỗi im lặng; import/export DB không bao giờ ghi/xuất credential. (nguồn: SAB-Store, ComparableTransaction)
