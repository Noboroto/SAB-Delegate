# NestJS + Fastify — proxy, IP, rate limit, logging

- Chuỗi proxy Coolify: Traefik → web (Next) → server. Traefik GHI ĐÈ `X-Forwarded-For` client gửi (probe `X-Forwarded-For: 9.9.9.9` → chỉ thấy IP thật), khác proxy-manager nối thêm; `$remote_addr`/`req.ip` của hop sau = IP proxy cho MỌI request. **How**: Fastify `trustProxy` đặt theo số hop thật (Traefik [+ Next]); kiểm `req.ip` bằng probe trên prod trước khi bật/siết rate limit; Better Auth 1.7 bỏ XFF nhiều hop (null) nếu không khai `advanced.ipAddress.trustedProxies` → mọi request dồn MỘT bucket rate-limit; helper `toCidrs` throw lúc boot nếu entry không phải IP/CIDR (Better Auth lặng lẽ bỏ entry lạ). (nguồn: SAB-Store, JudgeHub)
- SSR fetch (Next → server qua URL nội bộ) không qua proxy ngoài nên `@fastify/rate-limit` là lớp chặn duy nhất; fetch ẩn danh không cookie bị key theo IP container web = MỘT bucket cho cả site (288 req/phút vs trần 200, trang người khác chết). **How**: forward `X-Forwarded-For` NGUYÊN VĂN từ proxy ngoài, không tự dựng lại chuỗi từ một địa chỉ; rate limit key theo user session khi có; trần đủ cho SSR; kiểm log `"ip":"10.x"` về 0 sau sửa. (nguồn: JudgeHub)
- Next `<Link>` prefetch mặc định trên route động KHÔNG có `loading.tsx` render CẢ trang trên server → 1 API call mỗi dòng bảng (429 cả site). **How**: đặt `loading.tsx` ở LEAF (phủ segment con); đo bằng trình duyệt thật (hover → 2 request `?_rsc=` nhỏ, 0 call API); `prefetch={armed ? null : false}` hover-gating; `prefetch={true}` vô hiệu hoá `loading.tsx`. (nguồn: JudgeHub)
- pino `redact.paths` KHÔNG hiểu `**`: `['*.apiKey','*.*.apiKey']` che 1–2 cấp (3+ rò); `['**.apiKey']` rò MỌI cấp và không báo lỗi (fast-redact không có `**`). **How**: liệt kê tường minh từng cấp lồng cho `token`/`accessToken`/`authorization`/`cookie`/`DISCORD_TOKEN`/`BETTER_AUTH_SECRET` và test bằng pino thật. (nguồn: JudgeHub, QR-Production-Manager)
- Upload qua proxy: location mặc định `client_max_body_size 1m` → 413 HTML từ proxy trước khi tới app; presigned URL ký bằng endpoint NỘI BỘ làm browser PUT hỏng (dev che mất do chạy trên host). **How**: đặt giới hạn proxy/Fastify `bodyLimit` > giới hạn app hoặc upload qua API; test live qua proxy thật, không gọi thẳng container. (nguồn: JudgeHub)
- Healthcheck container dùng endpoint không phụ thuộc DB; static handler fallback `index.html` trả 200 cho MỌI path → so Content-Type/body với asset thật. Sau deploy web mở bằng trình duyệt, không chỉ curl. (nguồn: student-papers-manager, dtl_app-master, laptop-shortlist)
- `undici` userland 8.11.0/8.11.1 làm `fetch` toàn cục của Node 24 trả gzip thô (byte đầu 0x1f) → Better Auth/discord.js không parse được JWKS/REST; 8.11.2 và 7.29.1 lành. Chẩn đoán phải đo TRONG tiến trình app (`node -e` riêng không tái hiện). **How**: discord.js 14 phụ thuộc undici → `pnpm ls undici` sau mỗi lần nâng discord.js/undici, đặt pnpm override `undici@>=8.11.2` nếu cần, đo `fetch` toàn cục + gọi REST Discord thật ở staging; undici mặc định `headersTimeout`/`bodyTimeout` 300 s. (nguồn: JudgeHub, Leaderboard, attendance-hcmus)
- Lỗi JWT/OAuth khó thấy: `jose` `clockTolerance=0` → host/container chậm 1 s thì `iat` ở tương lai → 400 "invalid id token", log Docker không nói lý do. **How**: hook log `iat/now/ageSec` (KHÔNG ghi token thô); so `date -u +%s` host/container với header `Date:` của `curl -sI`; kiểm NTP host Coolify. (nguồn: JudgeHub)
