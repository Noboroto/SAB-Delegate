# Better Auth (Discord OAuth, stateless) — đã đo

- Ghim version CHÍNH XÁC (không `^`) cho `better-auth`, plugin `@better-auth/*` và `pnpm.overrides` cho `@better-auth/core`; hành vi đổi theo bản (tới 1.7.3 core bỏ field `issuer` khỏi `accountSchema` làm guard tự viết chỉ kiểm issuer hỏng MỌI đăng nhập; không copy pin của repo khác — bản cài dùng khoá account `(providerId, accountId)`, đừng port check `account.issuer`). `node_modules/.pnpm` có thể còn thư mục mồ côi (4 thư mục 1.6.22 không có trong lockfile) → xác nhận version bằng `node_modules/better-auth` của app, dọn bằng `pnpm install --frozen-lockfile`. **How**: kiểm changelog + context7 trước khi nâng, đọc source theo tag GitHub khớp `package.json` khi hook chặn đọc node_modules (ghi "đọc từ source, chờ test xác nhận"), test boot cho guard tự viết. (nguồn: JudgeHub, Leaderboard, QR-Production-Manager, SAB-Store, attendance-hcmus)
- Nâng 1.3.8 → 1.7.7 không cần migration dữ liệu nhưng: body có field `input:false` (vd `role` ở `/update-user`) giờ 400 `FIELD_NOT_ALLOWED` thay vì bỏ qua; XFF nhiều hop bị bỏ nếu không khai `advanced.ipAddress.trustedProxies` (xem `mem:lessons/nestjs/http-and-runtime`); admin `create-user` cần `user:set-role`; `data` không ghi đè được role/email/name. Plugin `admin` mặc định gán `role: "user"` — không có trong catalog role của app thì vi phạm FK `User.role → Role.slug` → bắt buộc `admin({ defaultRole, adminRoles })` tường minh. (nguồn: SAB-Store, Leaderboard, QR-Production-Manager)
- Hook `databaseHooks.*` FAIL-CLOSED, không throw sau commit: hook `user.update.after` chạy sau khi dữ liệu commit nhưng TRƯỚC khi tạo session cookie → throw ở đây 500 tài khoản vừa verify và khiến họ không đăng nhập được; bắt lỗi + log, ghi cột phụ bằng Prisma trực tiếp (không đệ quy). `user.update.after` là chokepoint duy nhất phủ mọi đường set `emailVerified` (`afterEmailVerification` bỏ sót email-otp reset và link OAuth 2 nhánh). Logic "sau đăng nhập Discord lần đầu thì tạo hồ sơ/gán vai trò" đặt ở `user.create.after`/`session.create.after` bọc try/catch. (nguồn: JudgeHub, attendance-hcmus)
- Ngữ nghĩa hook (đo 1.7.7): `ctx.path` là route pattern không có `/api/auth` (callback luôn `/callback/:id` với `params.id`); gọi `internalAdapter.createUser/createSession` trực tiếp cho `ctx === undefined` (không phải null) → `ctx?.path` undefined → nhánh fail-closed; `before` trả `{data}` chỉ MERGE, `false` huỷ, throw từ chối; `hooks.before` default-deny với `ctx.request` set — chỉ path allowlist (`/get-session`, `/sign-out`, `/callback/:id`, `/link-social`...) đi qua, còn `/update-user`, `/sign-up/email`, `/delete-user`, `/change-email`, `/set-password`, `/admin/*` trả 404; `auth.api.*` server-side bỏ qua deny. **How**: chỉ bật endpoint thật sự dùng (Discord OAuth + session) và viết test chạy qua handler thật để đo, không đoán; `npx auth@latest generate` cho schema tham chiếu để so với Prisma schema. (nguồn: attendance-hcmus)
- Provider: không đăng ký `clientSecret: ''` (500 mọi lần bấm nút, `CLIENT_ID_AND_SECRET_REQUIRED`); cột NOT NULL (`User.username`) mà OAuth `user.create` không cung cấp → 500 cho MỌI người dùng đầu tiên (user cũ ổn nên trông như chập chờn) → sinh trong `databaseHooks.user.create.before` (trả `{data}` chỉ MERGE); `mapProfileToUser` đặt `emailVerified` theo `verified` của Discord, email Discord có thể không có/không verified. (nguồn: JudgeHub)
- `user.image`: OAuth sign-up TỰ ghi `image` (Discord = URL CDN); `/update-user` và admin plugin mặc định cho ghi `image` tuỳ ý (URL theo dõi, `data:`) → chặn trong `databaseHooks.user.update.before` theo path; `cookieCache` bật thì `image` nằm trong cookie `session_data` (cộng dồn dễ vượt giới hạn header proxy → 502 `upstream sent too big header` ở callback); `accountLinking.updateUserInfoOnLink` ghi đè `name`+`image` và không lọc được; `overrideUserInfoOnSignIn` mặc định false. **How**: quyết định NGAY khi dựng có lưu avatar Discord hay không; không cần ảnh thì chặn ghi `image`/`name` từ client từ đầu. (nguồn: JudgeHub, attendance-hcmus)
- Account linking: tài khoản sở hữu `(providerId, accountId)` thắng; chưa có thì tìm user theo email và LIÊN KẾT ngầm khi provider ở `trustedProviders` hoặc provider báo `emailVerified` + hàng local đã verified. Chỉ Discord thì ít rủi ro; thêm provider thứ hai thì chặn liên kết ngầm vào tài khoản quản trị bằng `account.create.before` trả `false`. `trustedProviders` thiếu từng gây 401 khi link. (nguồn: attendance-hcmus, student-papers-manager)
- Cấu hình: cần `BETTER_AUTH_SECRET` (≥ 32 ký tự) + URL công khai tuyệt đối (client từ chối base URL tương đối → dựng từ `window.location.origin`); `trustedOrigins` chỉ cho client cross-origin; redirect URI Discord khớp domain; cổng dev cố định + ép base URL theo cổng; `127.0.0.1` ≠ `localhost` (test local thống nhất `localhost`); `getAuth()` lazy cache + `invalidateAuth()` khi đổi cấu hình. Lỗi đăng nhập lạ sau đổi domain/secret: xoá cookie / cửa sổ ẩn danh trước khi SSH (curl cho thấy server chấp nhận token → cookie cũ trùng). (nguồn: student-papers-manager, ComparableTransaction, coolify, attendance-hcmus)
- Rate limit sign-in của Better Auth 5 lần/15 phút (bộ đếm trong tiến trình) → test E2E dùng `storageState`; phản hồi sign-in 200 không chứng minh có phiên. Ghi avatar tự tải lên dùng compare-and-swap. (nguồn: JudgeHub)
- Không để xoá/hạ role admin cuối cùng (khoá dòng trong transaction, xem `mem:lessons/postgres-prisma/query-safety`); authorization thật ở guard Nest, không ở `proxy.ts`. (nguồn: ComparableTransaction)
