# Test Nest/Necord + Postgres

- Unit spec `new` thẳng class bỏ qua DI → app chết lúc boot mà 94 test xanh. Ví dụ tham số `fetchImpl?: SafeFetch` (type alias) phát `design:paramtypes = Object` → `UnknownDependenciesException`; `?` của TypeScript vô nghĩa với DI, phải `@Optional()`. **How**: mỗi service/module Nest/Necord mới có "boot spec" `Test.createTestingModule({imports}).compile()` qua container thật (override Prisma/pg-boss bằng `{}`); chứng minh guard ĐỎ được (gỡ `@Optional()` thì đỏ); assert dependency khác `undefined`. Lỗi đi theo cặp: service thứ hai cùng khuyết tật chỉ boot spec tìm ra. (nguồn: JudgeHub)
- Test Postgres thật: DB riêng mỗi file clone từ template (đã áp migration thật) hoặc Docker PG cổng cố định + schema `test_<run>` qua option `schema` của adapter-pg (client thứ hai trong test helper phải truyền cùng `schema`). Chi phí đo trên Mac: full suite 53 s → 66 s (DB/file) → ~85 s (template 20+ bảng). Data dir mang pid chủ; SIGKILL/OOM để postmaster sống sót → lần start sau dọn dir có chủ đã chết (kiểm `ps` pid thật là postgres). `TEST_DATABASE_URL` trỏ server ngoài thì server đó dùng-xong-bỏ. (nguồn: SAB-Store, attendance-hcmus)
- Test xanh chỉ chứng minh DB test, không chứng minh stage/prod đã migrate: global-setup tự `migrate deploy` vào DB test. Migration mới phải áp cả DB test TRƯỚC khi commit (spec live-DB đỏ "column does not exist" ngay trong commit hook tốn 2 lượt hook). **How**: sau deploy kiểm `_prisma_migrations` trên DB thật; `prisma migrate deploy` với `DATABASE_URL` trỏ DB test (mật khẩu lấy từ env container, không in). (nguồn: QR-Production-Manager, JudgeHub)
- Cần ít nhất vài integration test với Postgres thật cho truy vấn search/PATCH/transaction (mock không bắt được ILIKE không escape, lệch timestamp, rollback). Test thuần giữ DB-free; test chạm cấu hình dùng chung chụp ở `beforeAll`, khôi phục sau. (nguồn: JudgeHub, ComparableTransaction)
- Golden fixtures cố định validation của route khi đổi stack: file JSON giữ status + `errors[]` tham chiếu cho mỗi ca; replay qua app thật (một server listen); chỗ lệch được chấp nhận là khối `intentional` kèm lý do; capture từ chối ghi đè fixture có `intentional`. **How**: dùng khi chuyển validation sang Zod giữa lúc đổi stack. (nguồn: SAB-Store)
- Mật khẩu/secret trong test sinh lúc chạy (`fixturePassword(label)`/`fixtureSecret(label)` ghép chuỗi, không literal cạnh key `password`, không tiền tố nhà cung cấp); guard test quét `*.test.ts(x)`. Token Discord giả dạng `MTA...` dễ bị scanner bắt → fixture riêng, khai ĐÚNG tên file trong `.gitguardian.yaml` (`version: 2`, `secret.ignored_paths`), không bỏ cả cây test. (nguồn: attendance-hcmus, SAB-Store, Leaderboard)
- Test pass dưới nhiều timezone: chạy với `TZ=UTC` và `TZ=Asia/Ho_Chi_Minh`; formatter ngày giờ có test mốc biên (xem `mem:lessons/web/i18n-time-locale`). Dùng helper render có `<App>` + next-intl provider cho web. (nguồn: QR-Production-Manager, Leaderboard)
- Đừng skip/xoá test cho qua cổng; fixture bịa để qua thì không (seed thực tế thì được). Điều tra flake phải chụp tên test + message trước khi rerun. (nguồn: ComparableTransaction, SAB-Store)
