# Vitest — cạm bẫy đã đo

- Chạy một spec: `pnpm --filter <ws> test <spec>` KHÔNG có `--` (có `--` thì thành `vitest run "--" "<spec>"`, vitest bỏ filter: 74 file/994 test thay vì 1 file/22 test, 167 ms) — hoặc `npx vitest run "<path>"`. Path có ngoặc (route group Next `app/(app)/...`) không khớp kể cả escape → lọc bằng chuỗi con không có ngoặc. **How**: viết lệnh đúng thẳng vào prompt subagent, đừng bảo "trích tài liệu". (nguồn: JudgeHub, Leaderboard, QR-Production-Manager, attendance-hcmus)
- Vitest chỉ transpile, không typecheck: test thiếu 2 field bắt buộc của fixture vẫn 11/11 xanh, lỗi chỉ lộ ở `next build` (TS2739); chỉ `pnpm typecheck`/`nest build` bắt lỗi kiểu. Đọc log docker build bằng `grep -iE "failed|error|Built"`, không `| tail -3` (dòng `failed to solve` nằm TRƯỚC output lệnh nối sau). (nguồn: attendance-hcmus, JudgeHub)
- `beforeEach(() => mock.mockReset())` (arrow thân biểu thức trả hàm: `mockReset/mockClear/mockRestore`, `vi.fn()`, `vi.spyOn()`) bị Vitest 4.x chạy như teardown sau test → unhandled rejection đổ cho test KHÁC (Leaderboard 13 file, JudgeHub 6 chỗ). **How**: thân khối `{ ... }`; thêm lint rule hoặc grep guard (`[[:space:]]`, `git grep -E` không hiểu `\s`). Hay dính khi mock Prisma/discord.js. (nguồn: JudgeHub, Leaderboard, attendance-hcmus)
- `isolate:false` nhanh gấp 3–4 (api solo 24,7–102 s → 7,3 s) nhưng chia chung module registry: `vi.mock` + import tĩnh dính module file khác; lộ rõ bằng `--maxWorkers=1 --sequence.shuffle --sequence.seed=<n>` (~40–50% fail trước khi sửa). **How**: `vi.hoisted` + `vi.resetModules()` + dynamic import trong `beforeAll`, env lưu/khôi phục (không `delete`), `afterAll(() => { vi.restoreAllMocks(); vi.resetModules(); })`; cấm `vi.mock('@scope/*')` (mock workspace package rò mọi spec); không `vi.mock` service dùng chung của Nest (khác identity class → "can't resolve dependencies") mà `vi.spyOn(Class.prototype, ...)`; `unstubGlobals: true`. Đỏ/xanh đổi giữa các lần chạy của cây không đổi = order-dependence, không phải flake. (nguồn: Leaderboard, QR-Production-Manager, JudgeHub)
- Client mạng (pg-boss, Prisma pool, discord.js `Client`) mở lúc import trong metadata `@Module` mà thiếu listener `'error'` → `EnvironmentTeardownError: Closing rpc while "onUserConsoleLog" was pending`, mọi test xanh nhưng exit 1 đổ cho spec không liên quan. **How**: gắn handler `error`, không mở kết nối trong decorator lúc import; chẩn đoán bằng `--maxWorkers=1` và đếm dòng "Unhandled error event". (nguồn: Leaderboard)
- Supertest `request(app)` mỗi request tạo server tạm → `read ECONNRESET`/timeout 30 s dưới full suite song song. **How**: Nest + Fastify dùng `app.inject()` hoặc MỘT `app.listen()` chung mỗi file; đặt `maxWorkers` cố định trong config; thấy flake thì chụp tên test + message trước khi rerun. (nguồn: SAB-Store)
- Stub gọi callback trong thân render (`onCropComplete(...)`) mà cha `setState(object mới)` → vòng lặp vô hạn, `vitest run` không in gì, bỏ qua `testTimeout`. **How**: gọi trong `useEffect(..., [])`; im lặng quá ~1 phút thì chạy từng file riêng để khoanh. (nguồn: JudgeHub)
- Test AntD 6 (happy-dom): bọc `<App>` khi component gọi `App.useApp()` (không thì `message` undefined hoặc rơi vào fallback context-less → xanh giả); Form error không có `role="alert"` → assert `aria-invalid`; Modal confirm render tiêu đề 2 lần (`findAllByText`); class loading của nút trễ 1 tick (`waitFor`); trang `use(params)` cần `await act(async ...)`. Suite web exit 1 ngẫu nhiên "window is not defined" sau khi test xanh: `setTimeout` của `@rc-component/util@1.13.0` `useDelayState` không cancel khi unmount → pnpm patch (`pnpm.patchedDependencies`) hoặc nâng bản đã vá. (nguồn: Leaderboard, QR-Production-Manager)
- Chẩn đoán timer rò sau teardown: setup file tạm đặt ĐẦU `setupFiles` bọc `globalThis.setTimeout/clearTimeout`, ghi `new Error().stack`, in stack timer nổ sau `afterAll`; config tạm đặt DƯỚI thư mục web (config ở /tmp không resolve), tắt dep optimizer; xoá file tạm sau. (nguồn: QR-Production-Manager)
- Mock Prisma trả đúng giá trị đã cho nên không bắt được ILIKE không escape hay lệch timestamp; vitest `renderToString` không dùng biến RSC nên "Element type is invalid" vẫn xanh; guard test quét phải neo vào LỜI GỌI (call site), không neo hình dạng chuỗi (audit-action guard mù: 68.790 hàng prod lọt vì giả định SCREAMING_SNAKE). Khi mock `next/headers` quét `vi.mock(` lẫn `vi.doMock(`. (nguồn: JudgeHub)
- Test hàng loạt đỏ (≈59 fail ở ~10 file Prisma/S3) thường chỉ do Docker/Postgres tắt → `docker compose ps` trước khi đổ lỗi logic; không chạy vitest song song docker build (CPU đói làm Docker trả lỗi). (nguồn: ComparableTransaction)
